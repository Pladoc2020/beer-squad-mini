# ПИВНОЙ СКВАД МИНИ

Полностью статический сайт на React + Vite + TypeScript + React Router. Шесть оригинальных SVG-портретов, 14 демоматчей, вычисляемая статистика, локальный редактор, Web Audio и скрытая змейка. Всё содержимое демонстрационное. Внешних API, Steam ID, платных библиотек и backend нет.

## 1. Установка

Установите Node.js 22.12 или новее (рекомендуется Node.js 24 LTS) с npm. Распакуйте архив и откройте терминал в папке `beer-squad`, где находится `package.json`.

```sh
npm install
```

Для точного повторения версий из `package-lock.json` можно использовать `npm ci`.

## 2. Локальный запуск

```sh
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://127.0.0.1:5173`). Для остановки нажмите Ctrl+C. Не открывайте `index.html` двойным кликом: приложению нужен HTTP-сервер.

## 3. Production build

```sh
npm test
npm run build
npm run preview
```

`build` сначала проверяет TypeScript, затем создаёт готовый сайт в `dist/`. Для публикации нужна только эта папка. `preview` показывает готовую сборку локально. Тесты проверяют импорт, хранилище, вычисление статистики и правила змейки.

## 4. Cloudflare Pages

### Простой способ: загрузить готовую сборку

1. Выполните `npm run build` или используйте приложенный архив `cloudflare-pages-dist.zip` с уже собранной демоверсией.
2. В Cloudflare откройте **Workers & Pages → Create application → Pages → Use direct upload** (названия кнопок могут отличаться).
3. Укажите название проекта и загрузите содержимое `dist/` или архив готовой сборки. В корне загрузки должны находиться `index.html`, `_redirects`, `logo.svg`, папки `assets/` и `avatars/`.
4. Нажмите Deploy. Cloudflare выдаст адрес `название.pages.dev`.

### Автоматическая публикация из GitHub / GitLab

1. Поместите исходники в репозиторий. `node_modules/` и `dist/` добавлять не нужно.
2. Создайте Pages-проект через **Import an existing Git repository**.
3. Если репозиторий содержит сам проект в корне, Root directory оставьте пустым. Если проект лежит во вложенной папке, укажите её.
4. Build command: `npm run build`. Build output directory: `dist`. Переменная окружения `NODE_VERSION`: `24`.
5. Сохраните настройки и опубликуйте. Последующие коммиты будут запускать новую сборку.

`public/_redirects` содержит `/* /index.html 200`. Vite копирует файл в `dist`, поэтому прямое открытие `/admin`, `/matches` и других SPA-маршрутов работает на Pages. Backend и Pages Functions в этой версии не нужны.

## 5. GitHub Pages

В проект уже добавлен `.github/workflows/deploy-pages.yml`. Он сам установит зависимости, соберёт `dist/` и опубликует сайт после каждого push в ветку `main`. В workflow используется `VITE_BASE_PATH`, поэтому проектные ссылки работают в адресе вида `https://ВАШ_НИК.github.io/beer-squad-mini/`; `dist/404.html` сохраняет прямые маршруты React.

После загрузки файлов в репозиторий:

1. Откройте репозиторий → **Settings → Pages**.
2. В **Build and deployment → Source** выберите **GitHub Actions**.
3. Откройте вкладку **Actions** и дождитесь зелёного workflow **Deploy to GitHub Pages**.
4. Адрес появится в **Settings → Pages**. Если репозиторий называется `beer-squad-mini`, адрес будет `https://ВАШ_НИК.github.io/beer-squad-mini/`.

GitHub Pages публикует статические файлы, поэтому локальная админка и `localStorage` работают отдельно в каждом браузере. Для обновления production-данных измените `src/data/seed.json`, сделайте commit и дождитесь нового workflow.

Direct Upload и Git integration выбираются при создании проекта; для смены способа удобнее создать новый Pages-проект. Документация: [Vite на Pages](https://developers.cloudflare.com/pages/framework-guides/deploy-a-vite3-project/), [Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/), [Redirects](https://developers.cloudflare.com/pages/configuration/redirects/).

## Как пользоваться /admin

Внизу сайта есть кнопка **SYS / CONTROL**. Можно также открыть `/admin` напрямую. Пароля нет: редактор меняет только вашу локальную копию, а не общий сайт.

1. Выберите вкладку и запись слева. Измените поля и нажмите **СОХРАНИТЬ**.
2. **+ ДОБАВИТЬ ЗАПИСЬ** создаёт новую запись с уникальным ID.
3. **↑ ВЫШЕ / ↓ НИЖЕ** меняют порядок записей. На главной порядок определяет, кто первым занимает выбранный слот; все дополнительные участники попадают в отдельный резервный ряд.
4. Галочка **Активен** скрывает игрока с главной и из состава, сохраняя его участие в матчах. Роль — произвольный текст, `displaySlot` — визуальная позиция.
5. Герои и достижения вводятся по одному в строке. В дополнительные показатели вводите строки `название = значение`.
6. Аватар: путь вида `/avatars/my-photo.webp`, HTTPS-ссылка или локальная загрузка PNG/JPEG/WebP/GIF до 2 МБ. Загруженное изображение хранится внутри JSON. Для больших коллекций лучше класть картинки в `public/avatars/`.
7. **EXPORT DATA** скачивает `squad-data.json`. **IMPORT DATA** проверяет файл и после подтверждения заменяет базу. **RESET DATA** после подтверждения восстанавливает seed.

Неправильный JSON не заменяет сохранённые данные. При недоступном хранилище или заполненной квоте редактор показывает ошибку. Удаление игрока удаляет и его строки из сохранённых матчей; для сохранения статистики используйте скрытие.

Изменения этой версии сайта сохраняются только в этом браузере. Для постоянного обновления production-версии экспортируйте JSON и замените исходные данные проекта.

Для общего обновления: экспортируйте JSON, замените им `src/data/seed.json`, пересоберите и опубликуйте `dist`. Браузер, в котором уже есть локальные правки, продолжит показывать их: импортируйте новый JSON или нажмите RESET DATA. Разные домены и порты имеют разные localStorage.

## Как добавить матч

Откройте `/admin` → **МАТЧИ** → **+ ДОБАВИТЬ ЗАПИСЬ**. Заполните дату, длительность в минутах, режим, результат и примечание. Нажимайте **+ УЧАСТНИК МАТЧА**, выбирайте игрока, героя и K/D/A. Сохраните. Фильтры и статистика обновятся автоматически. Один игрок может участвовать в матче только один раз; скрытого игрока тоже можно включать в матч.

## Звуки, движение и пасхалка

Звук выключен при каждом открытии страницы. Включается кнопкой **SOUND: ON**, рядом появляется громкость. Все звуки синтезируются Web Audio API: hover, click, glitch, error, success, открытие банки и шум. Автовоспроизведения и чужих записей нет.

Семь быстрых кликов по маленькому логотипу в шапке открывают **ПИВНУЮ ЗМЕЙКУ**. Промежуток между кликами — не больше двух секунд. WASD, стрелки и экранные кнопки; Esc закрывает окно. Есть пауза, ускорение, локальный рекорд, Mango (+3), Rapier (+5) и Aegis (+2 и одно возрождение). При уходе со вкладки игра ставится на паузу.

Системная настройка «уменьшение движения» отключает CSS-анимации и деформации. Змейка сохраняет необходимое для игры движение, но не запускается автоматически. На touch-устройствах используется обычный курсор. Данные читаются без внешних шрифтов, изображений и API.

## Структура и будущий backend

```text
public/              SVG-ассеты и SPA redirects
src/
  App.tsx            оболочка, навигация и маршруты
  main.tsx           запуск приложения
  pages/             главная, разделы базы, админка
  features/          змейка и независимые правила игры
  data/seed.json     исходная база версии 1
  hooks/             контекст данных приложения
  services/          repository, DotaDataProvider, Web Audio
  styles/            цвета, layout, адаптивность, эффекты
  types/             Player, Match, HistoryEvent, Shame, SquadData
  utils/             вычисление статистики
scripts/test.cjs     небольшой запускатель тестов
tests/               проверки данных, статистики и игры
```

`SquadRepository` отделяет хранение от UI. Для backend замените `LocalSquadRepository` на сетевой репозиторий и адаптируйте контекст к асинхронной загрузке. `DotaDataProvider` имеет `LocalDotaDataProvider`; будущий `OpenDotaDataProvider` может реализовать тот же интерфейс. Steam ID можно добавить в модель позже. Workers/D1/R2 и авторизацию сейчас не имитируем.

Статистика вычисляется из `matches`: результаты, winrate, средний и лучший KDA, герои, длинные игры и максимальные серии. KDA = `(kills + assists) / max(1, deaths)`. Средний KDA — среднее по участиям игроков, не отношение сумм. Серии считаются по датам, при одинаковой дате — по ID. Поле `Player.stats` предназначено для дополнительных ручных показателей.
